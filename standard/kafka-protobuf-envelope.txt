Kafka protobuf envelope standard

Kafka record value:
Use serialized EventEnvelopePb bytes as the Kafka message value.

EventEnvelopePb purpose:
EventEnvelopePb is the stable routing envelope. It carries cross-cutting metadata:
- event_id
- command_id
- event_type
- occurred_at
- payload

Envelope payload:
The payload field should contain serialized protobuf bytes for the concrete event, command, or reply type, for example:
- PostTransactionRequestPb
- PostTransactionReplyPb

Why use protobuf bytes in both layers:
1. Kafka transports bytes natively, and protobuf gives compact binary encoding.
2. EventEnvelopePb gives every consumer a common metadata shape before it knows the concrete payload schema.
3. The payload protobuf keeps each event type strongly typed and independently evolvable.
4. The envelope can be parsed first for routing, tracing, idempotency, and observability; the payload can be parsed only after event_type is known.
5. This avoids JSON/string parsing on hot paths and keeps producer/consumer contracts generated from proto definitions.

Boundary rule:
Protobuf is the wire format. After the listener parses the envelope and payload, internal service control flow should use domain/result objects instead of branching on protobuf transport fields.

Outbox rule:
Outbox rows may store the concrete payload protobuf bytes. The publisher wraps those bytes in EventEnvelopePb before sending to Kafka.
