I slightly redesigned my wallet_action logic, I use 5 types actions to represent asset movement in my wallet system:
1. RESERVE:
    before posting ledger: -wallet.available, +wallet.reserved, create reservation, +reservation.reserved
2. CONSUME:
    before posting ledger: -reservation.reserved, +reservation.pending_settle
    after posting ledger: -reservation.pending_settle, +reservation.consumed
3. TRANSFER_OUT:
    call post ledger
    after posting ledger: -wallet.reserved
4. TRANSFER_IN:
    call post ledger
    after posting ledger: +wallet.available
5. RELEASE:
    before posting ledger: -wallet.reserved, +wallet.available, -reservation.reserved, +reservation.released

RESERVE/CONSUME/RELEASE correspond to reservation operation inside a single wallet
TRANSFER_OUT/TRANSFER_IN correspond to transfer operation across two wallets

in this architecture, 2-step asset movement is like:
1. call reserve api: RESERVE
2.a call consume api: CONSUME, TRANSFER_OUT, TRANSFER_IN
2.b call release api: RELEASE

while atomic asset movement is like:
call transfer api: RESERVE, CONSUME, TRANSFER_OUT, TRANSFER_IN in a single wallet transaction
